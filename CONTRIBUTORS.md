## How attribution works here

There is no hand-maintained list to fall out of date. Attribution comes from the
commit graph itself, which is already the authoritative record:

| Mechanism | Effect |
|---|---|
| Commit author identity | An email linked to a GitHub account is counted automatically. Nothing to register. |
| `Co-Authored-By:` trailers | Co-authors are credited on the same commit. The repository asks for these where AI tooling contributed to a change. |
| GitHub contributors graph | Populated by GitHub from the same metadata; no configuration. |
| CLA sign-off | `CLA.md` sign-off is recorded in the commit trailer, so consent is provable from history. |
| Upstream history | This fork's history is never rewritten, so upstream authorship stays intact and permanently visible. |

## How to be credited

1. Open a pull request against `main` and sign the CLA.
2. Merge with **Squash and merge**.

Your name lands in the table above on the next scheduled regeneration, or
immediately if you run the workflow from the Actions tab (**Run workflow**).

Co-author credit, when someone helped, comes from adding a `Co-Authored-By:`
trailer to the commit message:

```
feat(reader): keep the page-turn cursor on screen

Co-Authored-By: Name <email@example.com>
```

## Licensing and AI-assisted work

Contributions must sign the [`CLA.md`](CLA.md). Work that was substantially
written with AI assistance must say so in the pull-request description — see
[`AI_POLICY.md`](AI_POLICY.md). Disclosure is the requirement; the maintainer
owns and stands behind what is merged.
